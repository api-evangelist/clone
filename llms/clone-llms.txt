# Clone Robotics

> Clone Robotics develops musculoskeletal, intelligent androids and robotic hands built on its Myofiber artificial-muscle technology (pioneered 2021) and water-based hydraulics. Its developer surface is a first-party Python client (clone_client) exposing a high-level gRPC API to directly control the Clone Robot — muscles, valves, water-pump pressure source, telemetry, and cameras — over the local network.

This file was generated by the API Evangelist enrichment pipeline from the public GitHub org and repo artifacts. Clone Robotics does not publish an OpenAPI/HTTP API; the control plane is gRPC (proto3) for physical robot hardware.

## Client & Packages
- [clone_client (Python, gRPC)](https://github.com/clonerobotics/clone_client): High-level API to directly control the Clone Robot. Install: `pip install git+https://github.com/clonerobotics/clone_client.git` (not on PyPI).
- [clone_client_env](https://github.com/clonerobotics/clone_client_env): Gym-like RL environment wrapper.
- [clone_client_sync](https://github.com/clonerobotics/clone_client_sync): Deprecated standalone sync wrapper (sync client is now native to clone_client).

## gRPC service definitions (proto3)
- [ControllerGRPC](grpc/clone-controller.proto): muscle impulses/pulses/pressures, lock/loose, pinch & hydra valves, water pump.
- [HardwareDriverGRPC](grpc/clone-hardware_driver.proto): low-level bus driver, node discovery, IMU/GaussRider sensor settings, telemetry pause.
- [StateStoreReceiverGRPC](grpc/clone-state_store.proto): telemetry stream, system info, pose estimation, joint & muscle models.
- [CameraDriverService](grpc/clone-camera_driver.proto): camera config, streams, sinks.
- [data_types](grpc/clone-data_types.proto): shared types and the ServerResponse/ErrorInfo/ErrorList error envelope.

## Derived artifacts
- [Conventions](conventions/clone-conventions.yml): gRPC transport, zeroconf/mDNS discovery, streaming, error envelope, versioning.
